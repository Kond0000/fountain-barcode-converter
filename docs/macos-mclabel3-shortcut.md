# mC-Label3 Print - macOSショートカット設定

LABEL PRINTの「mC-Label3で印刷」は、1ページPDFとページ別の実寸情報をZIPにまとめてDownloadsへ保存したあと、macOSのショートカットを起動します。ショートカットはZIPを展開し、各ページを別々のCUPSジョブとして順番に印刷します。WebアプリはCUPSやプリンターへ直接接続しません。

この設定は、直接印刷を利用するMacごとに1回必要です。Cloudflare PagesのURLは全員で共通ですが、プリンタードライバー、プリンター登録、ショートカット、ブラウザの許可はMacごとのローカル設定です。

> 以前の単一PDF版ショートカットを設定済みの場合も、ページ別印刷に対応するため、下記の内容へ更新してください。

## 前提

- Cloudflare Pagesで公開されたLABEL PRINTをブラウザで開けること
- macOSにmC-Label3のプリンタードライバーが設定されていること
- `lpstat -e`で、名前に`MCL32`を含むプリンターが1台だけ表示されること
- `lpoptions -p "プリンター名" -l`に`Custom.WIDTHxHEIGHT`が表示されること
- ブラウザのダウンロード先が`~/Downloads`であること

ブラウザで「ダウンロード前に各ファイルの保存場所を確認する」が有効な場合、直接印刷時にはDownloadsへ保存してください。

## ショートカットを作成する

1. macOSの「ショートカット」アプリを開き、新規ショートカットを作成します。
2. ショートカット名を正確に`mC-Label3 Print`とします。
3. 右上の詳細（`i`）を開き、`共有シートに表示`をオンにします。これにより、ブラウザから渡す`ショートカットの入力`が有効になります。
4. 「シェルスクリプトを実行」を追加します。
   - シェル: `/bin/zsh`
   - 入力: 入力欄をクリックし、候補から`ショートカットの入力`を選択
   - 入力の渡し方: `引数として`
5. [scripts/mclabel3-print-example.sh](../scripts/mclabel3-print-example.sh)の内容をシェルスクリプト欄へ貼り付けます。
6. macOSの「ショートカット」>「設定」>「詳細」で、`スクリプトの実行を許可`をオンにします。
7. 初回実行時にmacOSやブラウザからショートカットを開く確認が出た場合は、内容を確認して許可します。

> `入力`欄を空のままにすると、ショートカット自体は起動してもシェルにはJSONが渡らず、`ERROR:印刷ジョブが空です`で終了します。`共有シートに表示`を先にオンにしてから、シェルの入力欄に`ショートカットの入力`が表示されていることを確認してください。

## セットアップ後の確認

1. WebアプリでサンプルCSVまたは実データを読み込みます。
2. 印刷枚数を1枚にして`mC-Label3で印刷`を押します。
3. ZIPが`Downloads`へ保存され、ブラウザが`mC-Label3 Print`を開くことを確認します。
4. 印刷されない場合は、ショートカットの入力欄が`ショートカットの入力`、渡し方が`引数として`であることを再確認します。
5. ターミナルで`lpstat -W completed -o`を実行すると、CUPSが受け付けた完了ジョブを確認できます。

別のMacへショートカットを共有した場合も、プリンタードライバー、ショートカットのスクリプト実行許可、ブラウザから開く許可は共有先のMacで確認してください。

ショートカットの処理順は次の通りです。

```text
Shortcut InputのJSONを検証
-> Downloads内の印刷ZIPを最大10秒待機
-> ZIPとmanifest.jsonを検証して展開
-> lpstat -eでmC-Label3を検出
-> lpoptionsでCustom PageSize対応を確認
-> 各1ページPDFを固有の幅・高さでlpへ順次送信
-> 結果を通知
```

## ZIPの内容

Webアプリが作る`mclabel-{UUID}.zip`には、次のファイルが入ります。

- `manifest.json`: ページ順、PDF名、各ページの`widthMm`と`heightMm`（小数3桁までの文字列）
- `mclabel-{UUID}-p000001-{width}x{height}mm.pdf`のような1ページPDF

コピー枚数も独立したページPDFとして展開されます。高さが同じページも異なるページも、すべて1ページずつ印刷要求を送ります。

## CUPSへ送るコマンド

各ページについて、検証済みの値だけを使って次と同等のコマンドを実行します。

```sh
lp \
  -d "$PRINTER" \
  -o "media=Custom.${WIDTH_MM}x${HEIGHT_MM}mm" \
  -- "$FILE"
```

`fit-to-page`、`lp -n`、自動拡大縮小は使用しません。PDF自体も指定した実寸の1ページPDFです。

## 安全対策

- ZIP名、UUID、ページPDF名、ページ番号、幅、高さを固定形式で検証します。
- ZIP内には`manifest.json`と許可形式のPDF名以外を認めません。
- `/`、`\\`、`../`を含むZIP内パスを拒否してから展開します。
- 展開したファイルがシンボリックリンクの場合は印刷しません。
- 幅と高さは正の数値、小数3桁までに限定します。
- manifest、PDF名、Shortcut入力のジョブID・ページ数・寸法が一致することを確認します。
- `eval`は使用しません。すべての変数を引用符で囲んでCUPSへ渡します。
- `MCL32`を含むプリンターが0台または複数台の場合は印刷しません。
- `Custom.WIDTHxHEIGHT`非対応の場合は印刷しません。

## エラーと途中停止

シェル結果は、ZIP不在、manifest不正、プリンター不在、Custom PageSize非対応、ページ別の`lp`失敗を区別します。途中のページでエラーになった場合、それ以前のページはすでにCUPSへ送信済みで、失敗ページ以降は送信しません。

WebアプリはShortcutの印刷完了を取得できません。「Macショートカットを起動しました」は起動要求まで成功したことを示し、実際の印刷結果はShortcut側の通知で確認します。
