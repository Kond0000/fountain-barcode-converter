# 方針ページ復旧テンプレート

このファイルは、Notion上に正式タイトルの運用方針が存在しない場合だけ読む。Notionページが存在する場合は、その本文が常に正本であり、このファイルで上書きしない。

## 作成先とプロパティ

- 親データソース: `collection://48806c96-3a9b-486e-a44f-9e9ba43e6559`
- タイトル: `FOUNTAIN｜マニュアル運用方針（AIエージェント必読）`
- 業務領域: `管理`
- 対象: `管理者`
- 種別: `ルール・方針`
- 状態: `確認中`
- タグ: `FOUNTAIN`, `システム`
- 表示順: `10`
- 目安時間（分）: `8`
- 担当者: 接続中のFOUNTAIN管理責任者。特定できなければユーザーへ確認する。
- 最終確認日: 実際に内容を確認した日。復旧作業日を自動的に実機確認日とみなさない。
- アイコン: `🤖`

作成前にデータベースを再取得し、プロパティ名と選択肢が一致することを確認する。スキーマが変わっている場合は意味の近い現行項目へ適合させ、変更点を報告する。

## 本文に必ず含める内容

次の構造でNotionページを作る。表、チェックリスト、ページメンションを使い、総合案内からもリンクする。

### 冒頭

AIエージェントがFOUNTAINのマニュアルを作成・更新・整理する前に、必ず全文を読む正本であることをcalloutで明記する。

### 適用範囲

- マニュアル、FAQ、チェックリスト、仕様、更新履歴の作成・更新
- 統合、分割、並べ替え、分類変更
- データベースのプロパティ、選択肢、ビュー、表示順の変更
- 目次、総合案内、関連リンクの変更
- 状態変更、アーカイブ、削除

### 正本

- FOUNTAIN｜マニュアルデータベース
- 現在のデータソース
- FOUNTAIN｜マニュアル総合案内
- このページの正式タイトル
- Notion本文が正本で、スキル内テンプレートは消失時の復旧用であること

### AIの必須事前確認

1. データベースと最新スキーマを取得する
2. 正式タイトルを完全一致検索する
3. 方針ページを全文取得する
4. 見つからない場合だけこのテンプレートから作成し、再取得する
5. 総合案内、対象、関連ページを取得する
6. 新規作成前に重複を検索する
7. 目的、対象、正本、完了条件を整理する

Notion接続、権限、正本を確認できない場合は作業を止める旨を警告calloutで明記する。

### データベース登録ルール

タイトル、業務領域、対象、種別、状態、担当者、最終確認日、目安時間、表示順、タグの入力ルールを表にする。AIの新規作成・実質的変更後は原則`確認中`とし、人の確認なしに`公開`へ変更しない。

### 本文構成

必要に応じて、目的・完了条件、対象・前提、早見表、手順、チェックリスト、トラブル対応、関連ページ、更新履歴を使用する。空の見出しは作らない。

### 情報品質

- 結論と次の操作を明確にする
- 画面名、設定値、URLを実環境または一次情報で確認する
- 変更されやすい情報は公式情報で確認する
- 推測や未確認事項を断定しない
- 表、番号付き手順、チェックリストを用途に応じて使う

### リンク

- 新しいマニュアル群は目次を作り、総合案内からリンクする
- 個別ページから上位ページへ戻れるようにする
- 前提と次の手順を相互リンクする
- 重複記載より正本へのページメンションを使う

### 作成・更新・整理

- 既存ページの更新を優先する
- 新規ページは正しいデータソース配下へ作成する
- 編集前に対象ページを取得し、依頼範囲外の内容を保持する
- 削除、アーカイブ、移動は明示許可がある場合だけ行う
- スキーマ変更前に既存ページへの影響を確認する

### 状態管理

`下書き`、`確認中`、`公開`、`要更新`の意味とAIの扱いを表にする。`公開`は人が確認した正式手順とする。

### 完了前チェック

- 方針を全文読んだ
- 最新スキーマとビューを確認した
- 重複がない
- 必須プロパティを確認した
- 目的、手順、確認方法が依頼と一致する
- 上位・関連ページから辿れる
- 既存コンテンツを壊していない
- 更新後に再取得した
- URLと状態をユーザーへ報告する

### 優先順位

1. ユーザーの現在の明示指示
2. Notionの運用方針
3. スキルの実行手順
4. 個別ページの慣例

通常ルールから外れる場合は差分と理由を報告する。未承認の削除、公開、外部共有は行わない。

### 更新履歴

復旧日、復旧理由、使用したスキル名を記録する。
